# 演示与 GitHub 提交准备

本项目是一个已能运行的小型原型，不是已完成报名或已公开的 GitHub 仓库。

## 一分钟演示

1. 说清问题：一个“成功率”无法区分始终保持、丢失后恢复和数据缺失。
2. 运行：`node dist/grasp-audit.cjs examples/synthetic.csv`。
3. 展示 `f_late`：最后稳定段刚好达到 200 ms，因此恢复成立；不是只看最后一个布尔值。
4. 展示 `b_short` / `f_gap`：分别为录制截断和采样断档，不计入成功/失败分母。
5. 导出 JSON/CSV，说明可接入实际实验记录。
6. 展示测试，明确示例是合成数据，真实机器人验证尚未完成。

## 可用的简短项目介绍（自行复核后使用）

GraspAudit 是用 MoonBit 编写的离线灵巧抓取实验评估工具。它读取扰动前后的
抓取状态时间序列，通过可配置的观察窗口、持续保持阈值和采样质量检查，
区分保持、持续恢复、未恢复和数据不足，并按实验条件生成 Markdown、JSON、CSV
报告。项目重点是让评估规则可复现、结果可审计，避免短暂恢复或缺失数据被
误计为成功。当前版本提供合成样例、跨后端单元测试和独立参考实现对照测试；
尚无真实机器人性能验证。

## 上传 GitHub 前

- 按比赛官方要求确认赛道、原创/AI 使用披露、截止时间和材料清单。
- 理解 `docs/METRICS.md`，能解释为何最终恢复不同于第一次短暂恢复。
- 使用自己的账号新建仓库，建议名 `grasp-audit`；可见性由你决定。
- 上传本文件夹内容，保留 MoonBit 源码、测试、LICENSE 和 third_party。
- 不要上传私人数据、密钥、账号信息。`.gitignore` 已排除构建缓存。
- 可按自己账号修改 `moon.mod` 的模块名；如修改，必须同步修改
  `cmd/grasp-audit/moon.pkg` 中的导入并重新构建测试。
- 本地模块名 `grasp-audit/grasp-audit` 不代表已占用/注册 Mooncakes 名字；
  不需要发布到 Mooncakes 就能运行或上传 GitHub。
- 本项目的 CI 文件仅在你自己上传仓库后才可能运行；目前没有远程 CI 记录。

不要宣称已在实机验证、超过某论文或达到某个真实成功率。若没有真实实验数据，
就把它作为“评估工具原型”提交，明确范围。是否满足特定赛事要求由赛事方决定。
